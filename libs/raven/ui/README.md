# @raven/ui

Raven's shared player and HTML playback engine, extracted without changing browser behavior. The library does not import the web app, its API singleton or its library pages. Hosts supply an `Engine` (`html`, or `native` with a `NativePlayer`: a command channel and an event stream to a player in another process) and their `PlayerServices`, inside their own React Router and TanStack Query providers. The services reach the player's parts through the `usePlayerServices` store, not a context: the component that renders `<Player>` calls `useHostPlayer(services)`, which sets the store after each render that changes them and answers true once it holds this host's, and renders the player only then. That component's lifetime must be the player's, since the player reads where to resume on its first render; a host that swaps one player for another gives each its own component. Import `@raven/ui/styles.css` once for tokens, element defaults and component styles.

## Build and consume

Consumers resolve package exports from `dist`, never an alias to this project's source. Nx builds `@raven/core` before UI, and UI before web. From the repo root:

```sh
bun install
bunx nx run @raven/ui:build
bunx nx run @raven/ui:test
bun run dev:raven
```

The build cleans output, bundles ESM and CSS with Vite, emits declarations with TypeScript, then rewrites declaration aliases with tsc-alias. `dev` watches the library bundle; `dev:raven` runs that watcher alongside the server and web dev servers. Generated JavaScript is build output only; source and configuration are TypeScript. Hosts may pass `progress.duration`, `hostActions` and `favourite` in the player services, and a native host also `trackPicks`, `chrome`, `isVolumeFixed` and `unplayableNote`; the web passes only `favourite`, and without it the player shows no heart. Hosts may also pass `handoff` (another player that takes the title over: Unplayable's primary action and the settings menu's last, which pauses first and hands over the current position), `escapeHint` (the line under Unplayable's escape: left out, the VLC and IINA hint; `null`, none), `escape.icon` (`copy` when left out), `onEngineError` (the native engine's error, before Unplayable shows it) and `title.context` (where the title came from, first on the line under the title, before its year, picture and playback mode; the desktop passes "Downloaded from <server>" for a download). The web passes `handoff` only while "Open videos in Raven" (`opensInRavenPlayer` in the player preferences, off by default) is on.

Peer dependencies are React 19.3.0, React DOM 19.3.0, React Router DOM 7.18.4, TanStack React Query 5.103.1 and zustand 5.0.15, supplied by the host. `@raven/core` is a workspace dependency. All stay external to the bundle, including React's JSX runtime, so hosts share one React, router, cache and preference store.

The root entry exports Player and the primitives, keyboard hooks and checks (`useKeyShortcut`, `isShortcut`, `isTypingTarget`) and the other pieces web still needs. The design tokens' parser, the themes, the shortcut table, the track labels and `KEYS` live in `@raven/core`. It also exports `UnlockDialog`, which asks for a `secret` (`pin` or `adminPassword`, the `UnlockSecret` type) under an optional `hint` (left out, the web's own words) and leaves the call to the host: `unlock` sends what was typed and rejects with the server's reason, which the dialog shows; `onUnlocked` runs on success just before the dialog closes itself, and is where the host closes its prompt; `onClose` means dismissed without unlocking (Cancel or Escape) and never follows an unlock. The dialog opens on mount only, so a host that asks for the admin password and then the PIN keys it by `secret` and it opens afresh for each. The web's `PinPrompt` passes its API client's `unlock`, closes its prompt and reads every query again. Controls and ICON_NAMES support the existing design page. `@raven/ui/headless` is the entry with no DOM, no `react-dom`, no router and no stylesheet, which a React Native app imports: the video state (`videoReducer`, `initialVideoState`, `VIDEO_EVENTS`), `fromPlayerEvent`, the engine contracts (`ENGINE_KINDS`, `NativePlayer`, `sendQuietly`, `sourceKey`), the `PlayerServices` types, the `usePlayerServices` store with `useHostServices` and `useHostPlayer`, the player's queries (`playerQueriesFor`, `playerQueryKeys`) and the player preferences. It also holds raven's query layer: `ravenQueriesFor(api)`, every query the web reads, built over the `ApiClient` it is given; `createQueryClient` with `queryKeys` and `mutationKeys`; the `after*` invalidations; `edit`, `editAll` and `useOptimisticMutation` with the edits built on them; and the `useUnlockPrompt` store that a locked library's refusal opens. The data hooks are factories over a client too: `mediaMutationsFor({ api })`, `watchedChangeFor({ api })` and `serverEventsFor({ api, openEvents })`, which listens on the `ServerEventSource` that `openEvents` opens (the browser's `EventSource` on the web) for the events `SERVER_STREAM_EVENTS` names; `usePlaybackPolicy({ queries })` reads the playback settings through the queries it is given. The selection store (`createSelectionStore`) and the page backdrop (`usePageBackdrop`) live there as well. The web binds the queries and each data hook to its own client in `lib/queries.ts`, `lib/useMediaMutations.ts`, `lib/useWatchedChange.ts` and `lib/useServerEvents.ts`, and keeps its one cache in `lib/queryClient.ts`. `usePlayerPrefs` has no storage until the host calls `configurePlayerPrefs({ storage })` with a `StateStorage` (`window.localStorage` on the web and the desktop, AsyncStorage in the app) before anything renders; it then loads what the storage holds. Its `headless-check/` test, run by `test:headless` under its own empty `bunfig.toml`, imports it with no DOM global and scans `dist/headless.js` and its chunks for forbidden imports (subpaths and dynamic `import()` included) and for any read of a DOM global. `@raven/ui/canPlay` exposes the one built capability module used inside Player and by web's playback notes. `@raven/ui/designTokens` derives the design page's tokens from the shared SCSS (`designTokens`) and each theme's colours from `themes.scss` (`themeTokens`), inlined as text at build so a host without a stylesheet, the device app, reads them as data. `@raven/ui/styles.css` is the stylesheet; its separate build entry avoids leaking SCSS source aliases into public declarations.

## Tests

Bun uses happy-dom and the shared `tooling/web` SCSS loader. Tests beside the player and helpers exercise UI source with a local API fixture, the services store and a query/router harness: `renderWithProviders({ ui, services })` sets the services before the first render, a test host calls `useHostPlayer`, and `test-setup.ts` empties the store after each test. Web keeps the browser-host clipboard, progress/history and built-player integration tests. Web mocks the public capability and design-token modules, not UI source paths. The three player query keys are defined once here and reused by web, preserving cache invalidation.

UI and web each enforce at least 96% total line and 88% function coverage. Test harnesses, tooling and built dependency output are excluded, not production player functions. Hardware, native playback and desktop-specific UI are outside this extraction.
