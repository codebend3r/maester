# Claude context for Wren on the web

`@raven/music-web` is Wren in a browser: the same app as `@raven/music` (`apps/raven/music`, Wren for iPhone, iPad and Android), screen for screen, built with React 19, Vite 8, react-router-dom, TanStack Query, zustand and SCSS modules. The rules that apply to it are in the root `CLAUDE.md` and `apps/raven/CLAUDE.md`, and what Wren is and does is in `apps/raven/music/CLAUDE.md`; this file holds what only the web app needs.

## One app, two codebases

- **A user-facing change lands in both apps.** Whatever changes a screen, a word, an order, a state, what a press does or a token here needs its counterpart in `apps/raven/music` in the same change, and the reverse. `.claude/agents/wren-parity.md` checks it, and reads the list under "Differences from the phone and tablet apps" below as the only differences allowed.
- **Every word comes from `@raven/wren`** (`libs/raven/wren`), the library both apps read their copy and pure models from: `KIT_COPY`, `PLAYER_COPY`, `SIGN_IN_COPY`, `HOME_COPY`, `countsLineOf`, `factsLineOf`, `WREN_THEMES` and `themeFor`, `RECENT_SORTS`, the recent searches' helpers, `nextPageOf`, a list's state and notice (`mergedOf`, `listStateOf`, `listNoticeOf`), `songLeadOf`, `shownLyricsOf` and the rest. A pure rule both apps need goes there with its test, never in one app and again in the other. This app declares no label, heading, placeholder, `aria-label` or message of its own; a word it needs that the library lacks is added there.
- **`src/parity.test.ts` fails when the two apps' pages differ.** It lists the route files under `apps/raven/music/app` (groups and `_layout` files left out), turns each into its path, and asserts `WREN_ROUTES` holds exactly that set. The web's own pages are `WREN_WEB_ONLY_ROUTES` (`/design`), which the apps have no file for and the test keeps out of both sets.

A kit component keeps the name and props of the apps' wherever a browser allows, so a screen ported from there reads the same. What differs by platform:

- **A size, a radius or a colour handed to a component is a token's name**, `SIZES.rowArt`, `RADII.thumb`, `COLORS.text3` from `theme/tokens.ts`, never a number: each value is the token's `var()`, and `tokens.test.ts` checks the names against `globals.scss`. `tokens.ts` holds only the tokens some component is handed; one a stylesheet alone reads gets a key when a prop first needs it. `AlbumArt` with no `size` fills the width it is given, so `AlbumTile`, `TileGrid` and `Shelf` take no `width`.
- **A press is a `Press`** (`ui/Pressable`): `href` makes a real link a browser can open in a tab, `onPress` a button, both a link that also tells `onPress`; it is one or the other, never neither, and only the button can be off (`isDisabled`) or a toggle (`isPressed`), only the link can replace the page (`shouldReplace`). A row with nothing to open is a `FactRow`, the apps' too. `AlbumTile`, `ArtistRow`, `NavigationRow`, `BackLink`, `TextLink`, `PageHeader`'s `back` and `SectionHeader`'s `seeAll` take one; `TabBar`'s items take `href`.
- **Wren shows one music library at a time.** `useMusicLibraries()` hands every listing `libraries`, the one library worn (`@raven/wren`'s `wornLibrariesOf`: the one picked in Settings' Library group while the server still has it, else the server's first), and `all`, every music library, for the place that picks. Home, Search and the collection read `libraries`, so a pick changes them all; the account's playlists and favourites are no library's and stay.
- **The data hooks are bound to the page's one `api`**, so they take no `session`: `useCovers()`, `useMusicLibraries()`, `useAllAlbums({ search })`, `useLibraryValues()`, `useNowPlaying({ track })`, `NewPlaylistForm`'s `onCreated` alone. The server's name is `useServerName()`'s: the Name given in Settings, else `STATUS_COPY.raven`.
- **`Card` and `Page` take a `className`** where the apps' take a `style`, and `TextField` takes an `<input>`'s own attributes with `onChangeText`. A form's submit is a `Button` with `isSubmit` and no `onPress`.

## Sign-in

- **The session is the browser's cookie session, as raven's web app keeps it.** The server's `/api/auth/config` (`queries.authConfigQuery`) names the Supabase URL, key and cookie; `lib/authClient.ts` builds `@supabase/ssr`'s browser client over it, loading Supabase's code only then; `stores/authSession.ts` reads the session, follows every change to it and hands out the access token; `lib/api.ts` puts that token on every `/api` call through `@raven/core`'s `refreshingFetch`, raven's web app's too, which answers a `signed_out` refusal with one refresh and one repeat, and signs out when the refresh is rejected. An `<audio>` and an `<img>` on the page's own origin are opened by the cookie.
- **Sign-in asks the raven account's email and password and nothing more**, as the apps do: no sign-up, recovery or confirmation. `lib/signIn.ts` names why one failed with the apps' kinds (`@raven/core`'s `SIGN_IN_ERRORS`: a field left empty, Supabase's `invalid_credentials`, out of reach, or a refusal in the service's own words), and `@raven/wren`'s `signInErrorsOf` says each in `SIGN_IN_COPY`'s words for both apps: empty fields are marked one by one under the banner, every other error is the banner alone.
- **`lib/access.ts` decides what a route shows** (`ACCESS_KINDS`): `loading` while the config or the session is read, `open` for a signed-in listener, `signedOut` otherwise. A server with accounts off (the fixture server) is `open` with no sign-in at all, as the apps open straight to Home under their bypass, and `/sign-in` there goes Home. A server out of reach is `signedOut`: sign-in shows, and says raven cannot be reached on a try, which reads the config again.
- **An account change empties what the last one left** (`lib/clearAccountState.ts`): the query cache is reset and the audio queue cleared, on sign-out, on another account signing in and on a refresh Supabase rejects; a renewed token keeps both.

## The shell and the breakpoints

- **The apps' phone layout is the web's under `48rem`, their tablet layout the web's from there.** Stylesheets are desktop-first with `@media (max-width: 48rem)`. Where code must know, `useFormFactor()` (`theme/formFactor.ts`, over `matchMedia` through `useLayoutUnder`, which Now Playing's own breakpoint reads too) answers `FORM_FACTORS.phone` or `tablet`, and what differs is a map `as const satisfies Record<FormFactor, ...>`: the shell's frames and sign-in's.
- **Now Playing's two rows start past `64rem`.** The apps lay Now Playing out in two rows only on a tablet held sideways; the web decides by width (`screens/NowPlaying/playerFormFactor.ts`): wider than `64rem` it is the two rows, and up to `64rem` the phone's panes, since the player's column, 30% of the width, is too narrow for the transport under that.
- **`shell/Shell.tsx` frames every route.** Under `48rem`: the page over a foot holding the mini player (`components/NowPlayingBar`, while a track is queued) and the kit's `TabBar` (on the four tabs only; a page opened from one keeps the mini player alone). From `48rem`: `Sidebar` beside the page (256 wide, a 76 wide rail of icons at `64rem` and narrower) and `PlayerBar` under both while a track is queued. `shell/chrome.ts`'s `chromeOf` reads the path as the apps' `useChrome` does: `bare` on `/sign-in` and `/now-playing`, which are drawn alone, `tabs` on a tab, `page` elsewhere. Until the listener is let in there is no chrome and no player.
- **The document scrolls, and the foot is `position: sticky`** at the screen's foot, taking its own room at the page's end, so a page never pads itself clear of the bars. `ToastHost` sits in the foot and floats above whatever it holds. The sidebar is sticky too, as tall as the screen less `--shell-foot`, which the shell sets to the player bar's height while it shows.
- **Every screen's root is `Page`** (`shell/Page`), a `main` padded as the apps' `usePageInsets` pads theirs: 36 above and 40 beside from `48rem`, the 20 gutter under it. It sets `--page-gutter`, which `Shelf` runs out through to the page's edges. A page that pads its top or its sides itself sets `--page-pad-top` or `--page-pad-side`, which `Page` reads before its own: the artist's, whose hero runs to the edges, sets both to 0.
- **Music plays through `@raven/ui`'s `AudioHost`**, mounted once in `Shell` above the routes, so leaving a page stops nothing. It needs no stylesheet: its only style hides a wrapper around two `<audio>` elements, which have no controls and so draw nothing anyway. **Never import `@raven/ui/styles.css` here**: it is raven's whole look in one file, its `globals.scss` tokens, themes and `elements.scss` element defaults with every component's module, and would restyle Wren's elements. `AudioHost` and `useKeyShortcut` (the sidebar's B) are the only things imported from `@raven/ui`'s main entry; everything else comes from `@raven/ui/headless`, which has no styles.
- **On Netlify, music plays from raven itself.** `netlify.toml` proxies `/api`, signed, to core's `DEFAULT_SERVER_ORIGIN` (`netlifyToml.test.ts` checks it), and `main.tsx` names that origin (`VITE_API_ORIGIN`) as the media origin through `@raven/ui`'s `startMediaOrigin` before anything plays, so a track goes there with a ticket and never through the proxy, as raven's web app does.

## Tokens

- **`src/styles/globals.scss` is the handoff's `tokens/tokens.css` and the apps' `wrenTokens.ts`, value for value**, under the repo's names: `--color-*` (the palette, `--color-night` and the brand's other fixed colours, `--color-art-*`), `--font-*`, `--font-weight-*`, `--font-size-*` and `--line-*` (a pair per `TYPE` entry), `--type-*` (each `TYPE` entry as one `font` value: `font: var(--type-row-title)`), `--tracking-*`, `--radius-*`, `--space-1` to `--space-10`, `--size-*` (the apps' `SIZE`, `SHELL_SIZES`, `PLAYER_SIZES`, `SEARCH_SIZES`, `DETAIL_SIZES`, `HOME_SIZES`, `THEME_SIZES` and `SIGN_IN_SIZES`), `--opacity-*`, `--duration-*`, `--ease-out`, `--shadow-*`, `--layer-chrome` and `--focus-ring`. Spacing, type and sizes are in rem, radii and hairlines in px. A token changed here has the same change in `wrenTokens.ts`.
- **`src/styles/_mixins.scss` holds the blocks more than one module writes**: `one-line`, `press-feedback`, `stacked-lines`, `meta-line`, `visually-hidden`, `hairline-ring`, `field-box`, `field-input`, `overline`, `card-surface`, `clamp-lines` and `picked-tile`. A module reads it by relative path, `@use '../../styles/mixins';`, since the dead CSS check compiles each module with sass alone, which knows no `@/` alias.
- **Wren wears one of nine themes** (`WREN_THEMES` in `@raven/wren`: Night, Paper, Garnet, Blush, Mint, Dracula, Midnight, Banana, Ember), each a `[data-theme='<name>']` block of `globals.scss` that gives the palette's names its values and its `color-scheme`; `:root` shares Night's block, so a page that names no theme is Night. The root's `data-theme` always names the theme worn: `followTheme` (`theme/followTheme.ts`) sets it from Settings' Appearance and the device's scheme (`theme/systemScheme.ts`, over `prefers-color-scheme`) once the app runs, and a small script in `index.html` does before first paint, reading the same `wren.prefs` key. Settings' Appearance keeps a `ThemeChoice` (`themeMode`, `theme`, `lightTheme`, `darkTheme`): Match device wears `lightTheme` or `darkTheme` as the device goes light or dark, One theme wears `theme` whatever the device says; `themeFor`, `withThemePicked` and `themeChoiceOf` (which also reads an older Wren's `appearance`) are `@raven/wren`'s, the apps' too. A block works on any element, so a theme's tile in Settings and its panel on /design wear `data-theme` themselves. `styles/themes.test.ts` fails when a theme lacks a block or a colour, or when a colour's value differs from the apps' `wrenTokens.ts`. A new theme is a name in `WREN_THEMES`, its scheme and its name in `SETTINGS_COPY`, a block here and a palette in the apps' `wrenTokens.ts`.
- **`--type-*` resets what `font` resets**, so the time, small and action-label entries add `font-variant-numeric: tabular-nums` after it, section and overline their `letter-spacing`, and overline `text-transform: uppercase`.
- **The fonts are `@fontsource/young-serif` and `@fontsource-variable/instrument-sans`**, as raven's web app loads them.

## Stores

- `stores/wrenPrefs.ts`: the theme choice, `homeSort`, `coverSize`, `libraryId` (the music library picked in Settings; null wears the server's first) and `serverName` (the Name given the server on this device; null says `STATUS_COPY.raven`), under the apps' `wren.prefs` key (`WREN_PREFS_KEY` in `@raven/wren`, with the guards) and version, each guarded on its own when read.
- `stores/recentSearches.ts`: the last searches, artists and albums opened from Search, over `@raven/wren`'s `withRecent`, `withoutRecent` and `mergedRecentsOf`, under `wren.recentSearches`.
- `stores/sidebar.ts`: whether the sidebar is folded to its icons (`wren.sidebar`), toggled by the Sidebar's button and by B (`@raven/wren`'s `SIDEBAR_KEY`), as raven's side menu is.
- `stores/toast.ts`: one message, hidden after `TOAST_MS` (2400 ms), and `toastFailure`.
- The queue and the volume are `@raven/ui/headless`'s `useAudioQueue` and `usePlayerPrefs`, read back from localStorage by `configureStorage` before the first route draws.

## Differences from the phone and tablet apps

Each of these is intended. Anything else that differs is drift.

- **No downloads.** A browser keeps no library of files for Wren, so there is no Download button on an album or a playlist, no Downloads category, shortcut or page (`COLLECTION_KINDS` leaves the segment out, and `/collection/downloads` opens Albums), no downloads group, storage meter or Remove all in Settings, no "Play your downloads" on Home's notice, and no downloaded check on a song row.
- **No "Streaming on cellular".** A browser cannot tell a mobile network from Wi-Fi, so Settings has no cellular quality and `useWrenPrefs` keeps only the theme choice, `homeSort`, `coverSize`, `libraryId` and `serverName`.
- **No CarPlay or Android Auto.** They are the phone's.
- **Search's Browse and Settings close up around the downloads.** Browse has three tiles (Albums, Artists, Songs), all in one row from `48rem`, with no Downloaded. Settings' wide layout keeps the tablet's two columns, the account and the server in the first and the appearance and About in the second, where the apps' downloads stand; the account's email is read from `/api/me`, so the card shows Sign out at once and the email as it comes.
- **The format and quality line has no "Downloaded" case**, since nothing plays from a download: `usePlaying` hands `@raven/wren`'s `qualityLineOf` only a file or a transcode.
- **Now Playing's output names the browser.** Where the apps say "This iPhone", the web says `NOW_PLAYING_COPY.devices.browser`: it knows no device name.
- **No server list, and the address is the build's.** The page talks to its own origin, so nothing can change the server; Settings shows its address read only, as the apps do, from `lib/serverAddress.ts`: the origin the build names (`VITE_API_ORIGIN`, raven's own on Netlify, port included), else the page's own. The server's name is the one given in Settings' Name field, else `STATUS_COPY.raven`, since the page has no server list to read one from.
- **Gestures become controls.** Drag to reorder, swipe to remove, swipe up on the mini player, drag a sheet down and a long press on a row have no pointer or keyboard equivalent, so each is a button a keyboard can reach: More on a row, Close and the scrim on a sheet, Move up, Move down and Remove in Up next. Hover and `:focus-visible` (with `--focus-ring`) are the web's additions.
- **An album's or a playlist's head scrolls with its tracks from `48rem`.** The tablet keeps the head in a column that scrolls on its own beside the tracklist; here the document scrolls, so the head goes with the page, and a head taller than a short window is never cut off.
- **A sheet is a centred dialog from `48rem`.** `BottomSheet` rises from the foot with its grabber under `48rem`, as the apps' does, and is a centred card on the wide layout, where a sheet across a desktop's whole width reads as a drawer.
- **The player bar ends with the volume.** Where the tablet's bar has Lyrics, Up next and Output, the web's has Lyrics, Up next and a volume line (hidden at `64rem` and narrower): a phone's volume is its buttons', a browser's is the page's own.
- **The cookie session instead of a token in the secure store**, since a browser has none and the cookie is what opens `<audio>` and `<img>` requests.
- **Sign-in has no "tickets off" step.** The apps stop there when the server cannot hand out media tickets, which they play by; the browser plays by its cookie, so `SIGN_IN_COPY.ticketsOff` and `continue` are never said.
- **A song's heart fades in at its row's end under the pointer or focus**, and stays while the song is a favourite; a press turns the favourite on or off, as the track menu's Like does. The apps have the menu's Like alone, since a touch screen has no hover.
- **A keyboard and a mouse get their own ways in.** A right click or the context menu key opens a track's sheet, as its More does; Escape closes Now Playing, as its close button does; Space plays and pauses from anywhere on the page unless a control with focus keeps the key (`usePlayPauseKey`), where the apps have the keyboard's and the lock screen's play key; and the volume steps by 0.05, the grain a pointer drags it by, where the apps' screen reader steps by 0.1.
- **Now Playing's two rows start past `64rem`.** The tablet lays them out whenever it is held sideways; a window of `64rem` or narrower keeps the phone's panes, as an upright tablet does, since the player's column would be too narrow for its transport.
- **Now Playing's artist link replaces the page.** The apps close the sheet and then open the artist; a link that replaces Now Playing in the history does the same, so Back from the artist returns to the page the player was opened over.
- **The A to Z rail measures where its list starts.** The apps place it by the header's known height; the web reads the list's top (`screens/Collection/useListStart.ts`, which watches the header through a ref it hands `CollectionHeader`) and keeps the rail between there and the shell's foot, so it always fits what shows.
- **The sidebar folds to its icons with B or its toggle**, as raven's web side menu does, and stays so across visits; at `64rem` and narrower it is that rail whatever the toggle says, so there the toggle is gone and B does nothing. The apps' tablet sidebar has no toggle, since a touch screen has no key to press.
- **Navigation is links.** A tab, a sidebar place, an album tile and a back link with somewhere to go are real links, so the browser's own gestures (a new tab, a copied address, Back) work on them.

## Running it

- `bun run dev:wren:web` starts `@raven/server` on 8484 and this app on <http://localhost:5185> (strict), whose Vite proxies `/api` to the server. `RAVEN_DEV_API_ORIGIN` (the shell's, else `apps/raven/.env`'s) points the proxy at another raven, as it does for raven's web app.
- **Against the fixture server**, which needs no account and holds one album (Morning Chorus by The Fixture Birds): `bun run nx run @raven/server:serve:fixture` listens on `127.0.0.1:8490` (`FIXTURE_SERVER.appPort`, or `RAVEN_FIXTURE_PORT`), then `RAVEN_DEV_API_ORIGIN=http://127.0.0.1:8490 bun run nx run @raven/music-web:dev`. Accounts are off there, so the app opens on Home with no sign-in.
- `build` writes `dist`; `netlify.toml` builds and serves it, with no functions, service worker or PWA manifest.
- **It is served from Netlify's `wren-player` site** (`wren-player.netlify.app`, custom domain `wren.maester.tv`), whose `/api` proxy is signed with the same `RAVEN_PROXY_SECRET` raven's own site holds. The site is linked to the repository as raven's is (base the repo root, package directory `apps/raven/music-web`): `netlify-ignore.sh` skips every push to main and builds a preview only when something the site bundles changed, and production builds only on a `vX.Y.Z` release, when `release.yml` calls the site's build hook (the `NETLIFY_WREN_BUILD_HOOK` secret).

## Tests

- `bun run nx run @raven/music-web:test` runs the bun tests (`*.test.ts`, `*.test.tsx`) over happy-dom and Testing Library, a test beside what it tests. They test behaviour: what renders and what a press does, by role and by `@raven/wren`'s words.
- `test/render.tsx`'s `renderWithProviders({ ui, route, behind, formFactor, authConfig, client })` renders inside a query client and a memory router in a window as wide as `formFactor`'s layout (the wide one unless told `FORM_FACTORS.phone`), on a server with accounts off; `renderKitWithRoutes(ui)` is that with a page (`KIT_PAGES`) for each address a kit piece can open; `signedIn({ client })` and `signedOut({ client })` set a server with accounts on. `test/viewport.ts`'s `atFormFactor` resizes a window already rendered.
- The fixtures the apps' tests use (`MUSIC`, `OK_COMPUTER`, `RADIOHEAD`, `AIRBAG`, `MIXTAPE` and their pages) are `@raven/wren/testing`'s (`libs/raven/wren/src/testing.ts`), the one copy both apps read. `test/music.ts` hands on the ones this app's tests name and holds `mockMusicApi()`, which has the page's `api` answer with them; restore it after `cleanup()`. A file whose every test needs it calls `mockMusicApiEach()` (or `mockMusicAndWritesEach()`, with what a page writes) once instead, which mocks before each test and restores after it. `mockQueueEach()` puts mocks in the queue's place before each test and hands them back, and `OK_COMPUTER_TILE` is what the album's tile is called aloud.
- happy-dom lays nothing out and loads no SCSS (`tooling/web/scss-modules.ts` hands a test each class's own name), so a layout, a breakpoint's look and what `:focus-within` shows are checked in a browser.
- **`/design` is Wren's design on one page, as raven's is raven's.** `src/screens/Design` draws five numbered sections (their words are `@raven/wren`'s `DESIGN_COPY`, as every other word is) under a sticky contents bar: the logo, the palette of each theme on its own ground (with the contrast of its text), every token but the colours and type styles at its true size, each `--type-*` style, and the kit's components in their states. It reads `src/styles/globals.scss` as text (`designTokens.ts`, through Vite's `?raw`), so it never falls behind the stylesheet; Bun cannot load `?raw`, so the import sits alone in `stylesheet.ts`, which `Design.test.tsx` mocks with a small stylesheet of its own. `PALETTES` holds one entry per theme of `WREN_THEMES`, read from that theme's `[data-theme]` block with `@raven/core`'s `parseThemes`, and each panel wears its theme's `data-theme`, so a new theme shows up there with its block in `globals.scss`. It is outside the listener's sign-in (it shows no music), outside the sidebar, and not a page of the apps.
