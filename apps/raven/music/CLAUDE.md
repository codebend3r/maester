# Claude context for Wren

`@raven/music` is Wren, raven's music app for iPhone, iPad and Android phones: an Expo app with `expo-router`, touch only, with a look of its own. Its design is `docs/superpowers/specs/2026-10-27-raven-audio-design.md` (PR 8 on), and its plan `docs/superpowers/plans/2026-10-30-raven-music-standalone.md`. The rules that apply to it are in the root `CLAUDE.md` and `apps/raven/CLAUDE.md`; this file holds what only Wren needs.

## Names

- The app is named Wren, so the Xcode workspace and scheme are `Wren` and the simulator build is `build/ios/Build/Products/Release-iphonesimulator/Wren.app`.
- The iOS bundle id and the Android package are both `app.netlify.wren`; the slug and the link scheme are `wren`. Anything hosted lives on Netlify.

## Shared with the device app

- **The fork and the pins are `@raven/app`'s.** Wren runs on `react-native-tvos` too, since the root `overrides` sets `react-native` for the whole workspace, and every Expo and React Native package is pinned to the version `@raven/app` pins. Read `apps/raven/app/CLAUDE.md`'s "Pins", "Bun's package store" and "Intl and the shared layer": `NODE_PATH` and `REACT_NATIVE_NODE_MODULES_DIR` on the Apple prebuilds, jest letting Babel through `node_modules/.bun`, `^build` before Metro, and `expo.autolinking.exclude` keeping reanimated, worklets and gesture-handler out of the native projects all hold here for the same reasons. A bump moves both apps together.
- **Sign-in and media access are `@raven/native`'s** (`libs/raven/native`), never a copy. `index.ts` imports `@raven/native/polyfills` before `expo-router/entry`. The native modules `@raven/native` uses (`expo-secure-store`, NetInfo) are autolinked through it; `@raven/audio`, which Wren imports itself, is a dependency of Wren's own and links on iOS and Android alike.
- **The build number and the variant** come from `@raven/native/headless` (`buildNumberOf`, `isDevelopmentVariant`), as the app's do: `GITHUB_RUN_NUMBER`, else 1, and `APP_VARIANT=development` for plain http to a LAN server (`NSAllowsLocalNetworking`, and Android's cleartext through `plugins/withCleartextTraffic.ts`).
- **No TV.** Wren has no `@react-native-tvos/config-tv`, no `EXPO_TV` and nothing from `@raven/app`'s layouts. Its colours come from `@raven/ui/designTokens`; the splash and Android's window are the default theme's `--color-night`.
- **Background audio.** `UIBackgroundModes` holds `audio`, and Android asks for `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, for `@raven/audio`'s media service.
- **Media3** is pinned to exactly 1.8.0 in `libs/raven/audio/android/build.gradle`: `react-native-video` 6.19.3's (`RNVideo_media3Version`), so the workspace builds against one Media3; a bump of either moves both. `@raven/audio`'s README says how its Android side works.

## Sign-in and the shell

- **Sign-in is the app's, step for step.** `src/screens/SignIn.tsx` asks the raven account's email and password only, through `@raven/native/headless`'s `signInFlowFor`, the device app's sign-in too, which holds the steps, the fields' state and the outcomes (it never asks for the PIN or the admin password); only the copy, the look and where it goes once done are Wren's. The account is kept under `wren.account` (`src/session.ts`); the server list and cookies keep the shared `raven.` keys, which Wren's own keychain holds apart.
- **`WrenRoot` reads the stores before any route,** pins `RAVEN_SERVER` (`pinRavenServer`), renews the access token a minute before it ends (`@raven/native/headless`'s `tokenRenewalFor`, the app's too), and guards the `(tabs)` group with `Stack.Protected`, so a listener signed out lands on `/sign-in`. `useWren()` gives the active server's `api` and `ravenQueriesFor(api)`, made once per server (`lastPerServer`), null until a server is active.
- **The tabs are Home, Library, Search and Settings** (`src/WrenTabs.tsx`, named in `WREN_TABS`), each labelled and drawn with raven's line icons through `@raven/native`'s `Icon` (the web's drawings from `@raven/ui/iconDrawings`, over react-native-svg, which Wren links through `@raven/native`). `src/theme/icons.ts` names the drawings Wren uses. Settings shows the account, the server, Sign out and the version from `#package`.
- **The cache is per account.** `src/queryClient.ts` holds Wren's one query client, and `forgetOnAccountChange` empties it whenever the signed-in account's id changes, signing out included, so the next account never sees the last one's playlists or favourites, and clears the queue, so the last one's music stops rather than counting listens or saving a book's spot under the next one's token; a renewed token keeps both.
- **The look is raven's default theme** through `src/theme/wrenTheme.ts`, which reads `themeTokens[DEFAULT_THEME]` and `designTokens` with `nativeTokens`; there is no theme picker.

## Browsing

- **Every list holds every music library's.** A music library is one `listingFor` lists by album. Library's Albums and Artists merge each library's listing (by title or name when there are several, an artist once), Songs reads `songsQuery`, which pages each library's tracks at `MUSIC_PAGE.most` to its end and then the next library's (passing over a library with none, so no page is empty but the last), asking for the next page as the list nears its end, and Playlists lists the account's. Home has one Recently added shelf per music library, its twenty newest albums (`recentAlbumsQuery`), and Search asks each library for albums, artists and songs once typing pauses.
- **`/album/[id]`, `/artist/[id]` and `/playlist/[id]`** sit in the guarded stack beside the tabs, each a `DetailRoute` over its query; the album's tracks are a `SectionList` by disc and the playlist's a `FlatList`, the head as the list's header, so a long playlist renders only what is on screen. The rows come from `@raven/ui/headless` (`albumDiscsOf`, `albumFactsOf`, `playlistTracksOf`, `playlistFactsOf`), as the device app's do. Play, Shuffle and a pressed row fill the shared `useAudioQueue`; holding a `TrackRow`, or its More, opens its menu: Play next, Add to queue, and Add to playlist, which appends it to one of the account's playlists.
- **Covers carry the server's cookies and the account's token** (`src/music/useCovers.ts`, over `@raven/native/headless`'s `serverHeadersFor` with the jar, the app's pictures' too), so a cover carries whatever cookies the jar holds; no client enters the PIN.

## Playing

- **`WrenAudioHost` plays the shared queue** (`src/music/WrenAudioHost.tsx`), mounted once in `WrenRoot` above the routes and keyed by the server, so leaving a screen stops nothing. It is `@raven/native`'s `useNativeAudioHost`, the device app's phone host too, over `@raven/audio` on both platforms, handed `mediaSourcesFor`, which it asks for a track's source only as one plays.
- **`audioItemOf` (`@raven/native`'s `src/music/audioItem.ts`) refuses what the player cannot decode.** The host asks it for each track, and it asks core's `canPlayAudio` for the platform (`Platform.select`, once) first: ALAC on Android gives null, and nothing is asked of the server. `nativePlayerOf` turns that null into `UnplayableTrackError`, and `useWindowedAudioHost` says `COULD_NOT_PLAY` and moves to the next track, stopping rather than circling when the queue holds nothing playable. Otherwise the file itself plays by its ticket, from `src/music/mediaSources.ts` (one `mediaAccessFor` per server, through `lastPerServer`).
- **The bar** (`src/components/NowPlayingBar.tsx`) shows while a track is queued: above the tab bar (WrenTabs' `tabBar`) on a tab, at the foot of a page the stack opened (`WrenRoot`), never on sign-in or Now Playing. Pressed, it opens `/now-playing`.
- **`/now-playing` is a modal sheet** (`presentation: 'modal'`): the cover, the scrubber and the volume (`Adjuster`, an `adjustable` a finger slides and a screen reader steps, since React Native has no slider and Wren takes no native one), Shuffle, Previous, Play or Pause, Next and Repeat, an audiobook's speed, and under them the Lyrics or the Queue (`Segments`). A synced line plays from where it is sung; the queue's rows (`queueRowsOf`) play, move up and go.
- **Render tests mock `@raven/audio`** in `src/test/jestSetup.ts`, since `WrenRoot` mounts the host on every screen and jest has no native player; a test reads `audioPlayer`'s calls.

## Running it

- `bunx nx run @raven/music:dev:ios` builds the development variant and runs it on the `wren-phone` simulator against Metro (`scripts/ci_wren.sh` makes it, an iPhone 16 or the runtime's newest iPhone, so run `bun run ci:wren` once first); `dev:android` runs it on the connected device or emulator.
- `build:ios` and `build:android` make the release builds, each running its `prebuild:*` first. `ios/`, `android/` and `build/` are generated and gitignored: change `app.config.ts` or a plugin, never the native projects.
- `test` runs the bun tests (`*.test.ts`); `test:screens` the jest-expo render tests (`*.render.test.tsx`), as in the app. `app.config.ts` is imported by its test through the package's `#app-config` import.
- The native targets and `e2e` need a Mac with Xcode or the Android SDK, so `verify` and `affected` leave them out, as they do the app's.
- **`e2e/` holds Maestro flows** (`appId: app.netlify.wren`) against `@raven/server`'s `serve:fixture`, whose open music library holds one FLAC album, Morning Chorus by The Fixture Birds, three twenty second tracks (First Light, Dawn Song, Open Sky), neither pinned nor in the hero so the device app's Home is unchanged. The build names the fixture with `EXPO_PUBLIC_RAVEN_BYPASS_ORIGIN` and the development variant, as the app's does (both Nx inputs of `build:ios`, `prebuild:ios` and `e2e`), so the app opens on the fixture with no sign-in. `steps/signIn.yaml` launches it clean; `signIn.yaml` lands on Home with the album under Recently added; `playAlbum.yaml` opens it from Library's Albums, presses Play, reads the first track's title off the bar (its label, "Now Playing: <title>, <artists>"), presses the bar's Next, pauses and reads the second's. Playback-control taps cap Maestro's settling wait so the twenty second track cannot finish while the driver waits for idle.
- **`bun run ci:wren`** (`scripts/ci_wren.sh`) runs CI's `🎵 Wren on iPhone` here: the libraries, the fixture server (reused when one listens on 8490), the `wren-phone` simulator (made once, then reused), the build, the pods check, the install and the flows on that simulator by its id, so another booted one is never driven. `🎵 Wren for Android` only builds the Release APK (x86_64, as the TV job's) and uploads it.
